# Lane: GitHub + Cloudflare, без аренды сервера

Код хранится в приватном GitHub. Cloudflare Worker выполняет обработку запросов, а Cloudflare D1 хранит ссылки и публичные снимки плейлистов. VPS, Node-сервер, PostgreSQL и адрес `API_ORIGIN` для этой схемы не нужны.

Один публичный домен: `https://lane-app.site`.

- `/` — страница Lane;
- `/s/<token>` — карточка трека, альбома, исполнителя или публичного плейлиста с отправителем;
- `/thumb/<token>.jpg` — уменьшенная квадратная обложка для предпросмотра в мессенджерах;
- `/v1/shares` — создание ссылок;
- `/v1/public/shares/:token` — чтение ссылки приложением;
- `/v1/public/playlists/:id` — публичный снимок плейлиста;
- `/.well-known/assetlinks.json` — привязка Android;
- остальные `/v1/*` — связь с уже работающим сервисом аккаунтов и библиотеки Lane.

## Что осталось подключить в Cloudflare

1. Добавить `lane-app.site` в Cloudflare и установить у регистратора предложенные NS, если это ещё не сделано.
2. В Workers & Pages создать Worker из приватного GitHub-репозитория. Имя Worker: `lane-share`. Папка проекта (Root directory): `sharing`. Зависимости: `npm ci`; команда публикации: `npm run deploy`.
3. Wrangler автоматически создаст базу `lane-shares` и привяжет её как `DB`, поскольку binding уже объявлен в `wrangler.jsonc`. Если Cloudflare предложит подтвердить создание D1, подтвердить его. Секреты и пароли базы не нужны.
4. При первом обращении Worker сам создаст таблицы в D1. Если автоматическое создание ресурса недоступно в выбранном способе публикации: создать D1 с именем `lane-shares`, прислать её Database ID и добавить его полем `database_id` в соответствующий binding в `wrangler.jsonc`. Database ID — публичный идентификатор, не пароль.
5. Привязать Custom Domain `lane-app.site` к Worker. Это уже указано в `wrangler.jsonc`. При конфликте убрать старую привязку домена к Pages/другому сайту.

Настраивать `API_ORIGIN` или поднимать собственный сервер не нужно. Worker использует тот же сервис аккаунтов, с которым Lane работал раньше (`https://api.tryliner.fun`). Если фактически приложение собиралось с другим `VITE_API_URL`, этот адрес нужно сохранить как `ACCOUNT_API_ORIGIN` в настройках Worker. Адрес должен быть HTTPS и отличаться от `lane-app.site`.

GitHub Pages для этой схемы не требуется. Старые workflows Pages ограничены каталогом `site`, чтобы не публиковать исходники приложения. Приватность репозитория сохраняется; страницы ссылок доступны получателям без входа.

Альтернатива Git-интеграции: в каталоге `sharing` выполнить `npm ci`, авторизоваться в Cloudflare и выполнить `npm run deploy`. Первая публикация также создаст D1 автоматически. При повторной публикации используется уже созданная база; данные не очищаются.

## Аккаунты и публичные плейлисты

Создание ссылки требует действующего аккаунта Lane. Worker проверяет access token через `/v1/me` у действующего сервиса аккаунтов и берёт отправителя из ответа. Произвольно указать чужой username в запросе создания ссылки нельзя. Пароли, refresh token и access token в D1 не сохраняются.

Для своего плейлиста выберите в Lane «Сделать публичным», затем «Поделиться». Worker запрашивает его через действующий сервис библиотеки, проверяет `isPublic`, сохраняет публичный снимок без локальных файлов, идентификаторов устройств и служебных данных. Перед каждым публичным открытием повторно проверяется список публичных плейлистов владельца. Когда плейлист стал приватным, удалён или проверка недоступна, содержимое не выдаётся.

Название и список треков плейлиста сохраняются на момент создания ссылки. Чтобы обновить снимок после изменений, поделитесь плейлистом ещё раз. Старые ссылки на этот плейлист получат обновлённый снимок. Одна и та же ссылка при пересылке продолжает показывать первоначального отправителя.

Для совместимости с действующим API используется тот же WASM-подписыватель, который уже входит в Lane. После обновления подписывателя приложения выполните из каталога `sharing` команду `npm run sync:signer`, затем опубликуйте обновление Worker. Этот файл не содержит токенов пользовательских сессий.

## Android и ПК

В конфигурации уже указан публичный SHA-256 сертификата существующего `release/Lane-1.7.11-local-avatar-playback.apk`. Если новый APK подписан тем же ключом, для App Links достаточно публикации домена. При другой подписи, например Google Play App Signing, нужно заменить или дополнить `ANDROID_SHA256_FINGERPRINTS` в `wrangler.jsonc`.

Приложение использует `https://lane-app.site` как основной API-адрес, а Worker передаёт обычные запросы действующему сервису Lane. Если в настройках сборки уже задан `VITE_API_URL`, установите его в `https://lane-app.site`. Сначала опубликуйте Worker, затем распространяйте новую сборку.

Для Android нужен новый APK: изменены Java-файлы, manifest и XML-ресурсы. Долгое нажатие на значок показывает «Моя волна», «Любимые», «Настройки», если launcher поддерживает App Shortcuts. На Android кнопка «Поделиться» вызывает системное меню отправки. На ПК ссылка копируется или передаётся через доступное системное меню.

На ПК карточка использует зарегистрированный приложением протокол `liner://share?id=...`; браузер может попросить разрешить открытие приложения. Встроенные браузеры мессенджеров могут потребовать нажатия «Открыть в Lane» или перехода во внешний браузер. Ссылка, полученная до входа в аккаунт, дожидается завершения входа.

## Проверка после публикации

1. `https://lane-app.site/health` возвращает `service: lane-share` и `database: true`.
2. `https://lane-app.site/.well-known/assetlinks.json` возвращает JSON с пакетом `com.therikky.lane` и правильным сертификатом, без перенаправления.
3. Проверить вход в Lane через новый домен.
4. Поделиться треком, альбомом и исполнителем. Открыть карточки без входа и перейти в приложение на ПК и Android, включая запуск закрытого приложения.
5. Поделиться публичным плейлистом, проверить другим аккаунтом. Сделать плейлист приватным: карточка и API перестают раскрывать содержимое.
6. Проверить три пункта меню значка Android.

После смены домена и установки обновления Android может понадобиться повторная проверка App Links:

```sh
adb shell pm verify-app-links --re-verify com.therikky.lane
adb shell pm get-app-links com.therikky.lane
```

Превью для мессенджеров формируется в серверном HTML через Open Graph. Сами страницы и API ссылок не кэшируются, но мессенджеры могут сохранять старое превью у себя.

## Ограничения и проверки

Локальные аудиофайлы, персональные миксы и закрытые плейлисты не публикуются. Ссылки доступны любому, у кого есть адрес. Ограничение — 100 новых ссылок на аккаунт в час; вставка проверяется атомарно в D1. Публичный снимок плейлиста ограничен 900 КБ. Работоспособность сервиса аккаунтов остаётся необходимой для создания ссылок и проверки публичности плейлистов. Папка `api/` не требуется для публикации этой схемы.

Проверка из корня проекта:

```sh
node sharing/worker.test.mjs
pnpm exec vitest run src/shared/utils/incomingLink.test.ts --environment node
pnpm exec tsc -b
node scripts/check-locales.mjs
```

Тесты Worker проверяют реальную SQLite-базу через Python стандартной библиотеки (без подключения к аккаунтам). Проверка сборки Worker из каталога `sharing`:

```sh
npm ci
npx wrangler deploy --dry-run
```

Локальный запуск: `npm run dev`. Wrangler создаёт локальную D1, а Worker инициализирует таблицы сам.

Документация: [автоматическое создание D1](https://developers.cloudflare.com/changelog/post/2025-10-24-automatic-resource-provisioning/), [Git-интеграция Workers](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/), [Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

## Синхронизация YouTube и Яндекс Музыки

Для синхронизации установите в Worker `lane-share` постоянный секрет `INTEGRATION_SESSION_KEY`. Сгенерируйте 32 случайных байта в Base64 и передайте их Wrangler из каталога `sharing`:

```sh
openssl rand -base64 32 | npx wrangler secret put INTEGRATION_SESSION_KEY
npm run deploy
```

При следующих публикациях сохраняйте этот ключ: он нужен для расшифровки уже подключённых интеграций. D1 хранит токены интеграций в зашифрованном виде и разделяет сессии по аккаунту Lane и провайдеру. Токены входа в Lane используются для проверки доступа к API.
